# lintalker

A Python port of the classic DECtalk speech synthesizer.

This package has no OVOS/plugin dependencies — it is a standalone
synthesizer library. An OVOS TTS plugin wrapper around it lives in a
separate repo.

The C reference source this is ported from lives at
[dectalk/lintalker](https://github.com/dectalk/lintalker) (this repo's C
counterpart is checked out locally as `lintalker-c`).

**What this means today:** `lintalker.api.synthesize_text(voice_dict, text)`
synthesizes English text end-to-end, verified frame-for-frame bit-exact
against the real C engine (`test/test_synthesize_text.py`) across
dictionary words, rule-fallback words, and multiple voices — including
note-driven singing voices (GoodNews/BadNews/PipeOrgan/Cellos) and
multi-clause text (input is split on `. , ! ?`, since a comma ends a
sentence-assembly cycle in the real engine too; all clauses of one call
share a single synthesis session the same way the real engine's `Talk()`
does, so clause-to-clause continuity is preserved, not just each clause's
own correctness). Word-by-word part-of-speech disambiguation
(`Morph.c`'s `ResolvePOS`) is ported, driving both phrase-boundary
placement and question intonation from real POS tags rather than
word lists. A word missing from the dictionary but ending in a plural/
3rd-person-singular "-S" (e.g. "dogs", "cats", "wishes") whose root IS in
the dictionary gets the root's real pronunciation plus the phonetically
correct suffix, instead of falling through to generic letter-to-sound
rules; the same applies to `-LY`, `-EST`/`-IEST`, `-ER`/`-IER`/`-ERS`/
`-IERS`, `-ED`/`-IED`, `-ING`/`-INGS`, `-ES`/`-IES`, `-CALLY`/`-BLY`,
`-MENT(S)`/`-IMENT(S)`, `-ABLE`, `-NESS(ES)`/`-INESS(ES)`, `-ISM(S)`,
`-OR(S)`, and the `-IZE` family (`-IZE`/`-IZED`/`-IZES`/`-IZING(S)`/
`-IZER(S)`) (e.g. "timed", "timer", "timing", "shorter", "magically",
"talked", "loves", "loveliest", "government", "arguable", "business",
"heroism", "editor", "itemize"). Bracket-delimited text commands
(`[[pbas200]]`-style) are supported for pitch/pitch-modulation/volume
changes, word emphasis (`[[emph+]]`/`[[emph-]]`), inserted silence
(`[[slnc500]]`, at the exact word position), comments (`[[cmnt...]]`),
version checks (`[[vers...]]`), changing the command delimiters
themselves (`[[dlim...]]`), and reset (`[[rset0]]`, recognized and
queued as a `C_reset` command that raises `NotImplementedError` when
applied, matching `do_ctrl`'s existing documented stub) and sync
(`[[sync12345]]`, a genuine no-op in the reference too), word
part-of-speech override (`[[xtnd mtk3 wpos 1]]`, at the exact word
position), and speaking-rate changes (`[[rate240]]`/`[[rate+20]]`, at
the exact word position, persisting across clauses) — pitch/mod/volume
are applied at the start of the clause they appear in, not the exact
phoneme position; see
`docs/architecture.md`. Cardinal numbers ("123" -> "one hundred and
twenty three") are also supported (`lintalker/_numbers.py`) -- see
`docs/architecture.md` for that feature's documented verification
caveat. Abbreviation periods (e.g. "Mr.", "Dr.", "St.") are recognized
via a dictionary lookup and do not end a sentence/clause
(`lintalker/_frontend.py`'s `_is_abbreviation_period`), matching
`FrontEnd.c`'s `tok->isAbbriv` check. The `nmbr` embedded command
(`[[nmbr LTRL]]`/`[[nmbr NORM]]`) switches digit-string tokens between
digit-by-digit reading ("123" -> "one two three") and normal cardinal
grouping. A plain 4-digit number starting with "1" (1001-1999, e.g.
"1984") is automatically read year-style ("nineteen eighty-four")
instead of as a grouped cardinal, matching the real engine's own
narrow, automatic `kYearSpecial` detection. Remaining known gaps:
`char`/`mode` embedded commands and
ordinal/decimal/currency/phone-number reading modes — see
`docs/architecture.md` for
specifics. You can still synthesize from an
already-built phoneme plan directly via
`lintalker.api.synthesize_phonemes()`, and there's a lower-level
`lintalker._engtop.engtop()` (single word) and `lintalker._frontend`
(tokenization only) if you need to build a custom pipeline.

## Install

```bash
uv pip install lintalker
```

## Usage

```python
from lintalker.api import synthesize_text, pcm_to_wav
from lintalker._data import Fred_Voice

pcm = synthesize_text(Fred_Voice, "hello, this is a test.")
pcm_to_wav(pcm, "out.wav")
```

Or, from an already-built phoneme plan:

```python
from lintalker.api import synthesize_phonemes, pcm_to_wav
from lintalker._data import Fred_Voice

# a phoneme plan for "hi" (see lintalker/_phonemes.py for phoneme ids)
phonemes = [23, 11, 54, 3, 33, 22, 23]
ctrls = [1, 268500993, 0, 268502089, 9, 16393, 2621440]
durs = [1, 26, 10, 54, 23, 5, 135]

pcm = synthesize_phonemes(Fred_Voice, phonemes, ctrls, durs)
pcm_to_wav(pcm, "out.wav")
```

See `examples/` for more, `docs/architecture.md` for how the port maps to
the C source, and `docs/creating-voices.md` for the formant-synthesis
theory behind a "voice" and how to build a new one.

## Voices

All 17 voices are bit-exact against the C reference: Fred, Kathy,
Princess, Junior, Ralph, Whisper, Zarvox, Trinoids, Bubbles, Boing,
Bells, Hysterical, Deranged, GoodNews, BadNews, PipeOrgan, Cellos.

## Testing

```bash
uv pip install -e .[test]
pytest test/
```

`test/test_voices.py` is the correctness backstop: it shells out to a
compiled build of the C reference (`lintalker-c`) and compares its
per-frame synthesis state and audio output against the Python backend,
voice by voice. It needs a local checkout+build of `lintalker-c` to run
(see `docs/architecture.md`).
